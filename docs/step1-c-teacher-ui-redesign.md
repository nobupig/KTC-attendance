# Step1-C 科目担当画面 UI抜本改善 設計メモ

## 1. 背景

Step0「教員未保存キャッシュFast化」とStep1-B「科目担当画面 授業カードUI最小改善」は完了し、本番反映済みである。本番WebアプリはVersion 182で、production Operationの`teacherUnsavedSummaryCache`、`teacherUnsavedDetailCache`と本番用triggerも準備済みである。この運用状況は作業依頼時に共有された情報であり、今回の調査では本番環境へ接続して再確認していない。

ローカルの`.clasp.json`と`src/config.js`は検証環境向きへ戻されている。Step1-C以降の開発は検証環境だけで行い、本番Apps Script、本番Spreadsheet、本番Webアプリには触れない。

Step1-Bでは既存の画面構造とAPI契約を維持しながら、授業カードDOM、時限表示、保存状態pill、操作ボタン、安全ガード、一覧概要を改善した。一方、ページ全体は引き続き「担当授業」と「出席入力」の2パネルを中心とする構造であり、今日の作業、過去授業検索、過去未保存対応の情報階層は大きく変えていない。

本メモは`html/teacher.html`と関連する既存APIをread-onlyで調査し、Step1-Cで画面全体を再構成するための設計方針をまとめたものである。実画面のスクリーンショット、実機操作、検証環境での動作確認はStep1-C実装後に別途行う。

## 2. Step1-Cの目的

Step1-Cは新機能を追加する工程ではない。科目担当教員が、既存機能だけを使って次の順序で迷わず作業できるよう、情報設計、レイアウト、視認性、操作の優先順位を再設計する工程である。

1. 今日担当する授業と進捗を確認する。
2. 対象授業を選ぶ。
3. 出席入力または欠席者なし保存へ進む。
4. 必要な場合だけ過去の未保存授業を確認し、対象授業を開く。

完了後に目指す状態は次のとおりである。

- 画面を開いた直後に、今日何件の授業があり、次に何をすればよいか分かる。
- 授業カードでは時限、科目、クラス、状態、主操作の順序が明確である。
- 入力中、保存済み、未入力、確認中、確認失敗を色だけに依存せず判別できる。
- 過去未保存は見落とさないが、今日の授業を常時押し下げない。
- Desktop、Tablet、Smartphoneのいずれでも、授業選択から入力開始までの導線が途切れない。

## 3. 非目的（Non-goals）

Step1-Cでは次を変更しない。

- GAS server-side APIの追加、削除、引数・戻り値変更
- 保存API、保存payload、保存データ仕様
- DB構造、Master、Operation、CONFIG
- teacher unsaved cacheのスキーマ、Fast API、rebuild処理、trigger
- `appsscript.json`
- 認証、権限、なりすまし機能の仕様
- 欠席リスク算出仕様
- 工学実験の班判定、集約、保存仕様
- 本番環境の設定、デプロイ、データ

Step2の複数授業選択、一括保存ボタン、batch API、一括保存状態管理は含めない。Step3の連続時限判定、統合カード、グループ単位入力、連続授業保存も含めない。

現行一覧APIは教室情報を返していないため、Step1-Cで教室を表示することも前提にしない。将来教室を表示する場合は、別工程でデータソースとAPI契約を確認する。

## 4. 現行UI構造

### 4.1 ページ全体

【現行コードから確認できた事実】

`html/teacher.html`はCSS、HTML、クライアントJavaScriptを1ファイルに持つ。静的なDOMは概ね次の構造である。

```text
body
├─ page-header
│  ├─ 「科目担当画面」
│  ├─ 日付・操作案内
│  ├─ 「ホームへ戻る」
│  ├─ 管理者向けなりすましUI
│  └─ 共通messageArea
└─ layout
   ├─ panel「担当授業」
   │  ├─ 過去未保存サマリー
   │  │  └─ 展開時の過去未保存詳細
   │  ├─ 「本日の授業」／「過去授業を検索」タブ
   │  ├─ 過去日付検索
   │  ├─ 時限ごとの選択
   │  └─ 授業一覧概要＋授業カード
   └─ panel「出席入力」
      ├─ 選択授業情報
      ├─ 最終保存情報
      ├─ 工学実験の班選択
      ├─ 上部操作ボタン
      ├─ 保存状態
      ├─ 出欠件数サマリー
      ├─ 学生一覧・状態ボタン
      └─ 下部保存ボタン
```

Desktopでは`.layout`が`360px 1fr`の2列である。900px以下では1列になり、「担当授業」パネルの後に「出席入力」パネルが続く。

### 4.2 初期表示とモード

【現行コードから確認できた事実】

- 通常の初期表示は`today`モードで、`getTodayClassesForCurrentUser()`を呼ぶ。
- 授業一覧取得後、`getSaveStatusForTeacherSessions()`で本日の保存状態を後読みする。
- 初期表示から7秒後、さらに800ms遅延して`getTeacherUnsavedSummaryFast()`を呼ぶ。本日の一覧表示を優先する設計である。
- URLで過去日付の授業が指定されている場合は`past`モードで開始する。
- 過去タブでは日付を選び、`getClassesForCurrentUserByDate(targetDate)`を呼ぶ。最後に検索した日付は`localStorage`へ保持する。
- `today`と`past`は`currentMode`、`classesCache`、`selectedClass`を共有し、同時に2つの一覧を表示しない。
- 未保存変更がある状態で授業、モード、班を切り替える場合は`window.confirm()`で確認する。

### 4.3 今日の授業カード

【現行コードから確認できた事実】

一覧上部には表示カード件数と、保存済み、未保存、一部保存済み、確認中、確認失敗の5種類のchipが常に表示される。

通常授業カードに表示される情報は次のとおりである。

- 時限
- 保存状態
- 科目名
- 学年・組
- 日付・授業回数
- 担当教員
- 最終保存時刻（存在する場合）
- `欠席者なしで保存`
- `欠席者を入力`

工学実験は同一日・時限・科目の関連クラスを1カードへ集約し、学年・組の代わりに「班選択して記録」を表示する。操作は`班を選択して入力`の1つである。

授業一覧APIが返す主な表示用項目は`classId`、`date`、`period`、`sessionNumber`、`subjectId`、`subjectName`、`grade`、`unit`、`term`、`curriculumUnit`、`teacherName`、`teachers`である。教室または教室相当のフィールドは返しておらず、現在のカードにも教室は表示されない。

`.class-card`には`cursor: pointer`、hover、activeの見た目があるが、カード本体にclick handlerは設定されていない。実際の操作はカード内のボタンと、別に表示される「時限ごとの選択」ボタンに設定されている。

### 4.4 出席入力へ進む操作

【現行コードから確認できた事実】

- `欠席者を入力`は`data-action="input-absence"`から`selectClass()`へ進み、名簿と保存済み出欠を読み込む。
- `欠席者なしで保存`は`data-action="no-absence"`から確認ダイアログを経て保存する。名簿は開かない。
- 本日の通常授業で保存状態が確認中または確認失敗の場合、`欠席者なしで保存`だけをdisabledにする。`欠席者を入力`は利用できる。
- 名簿では出席、欠席、遅刻、公欠の4ボタンを学生ごとに表示する。
- 状態を変更するとクライアントの`isDirty`が`true`になり、入力パネルに「未保存の変更があります」と表示する。
- 保存ボタンは入力パネルの上部と下部にある。
- 工学実験では、カード選択後に班一覧を取得し、班選択後に名簿を読み込む。
- 欠席リスクは名簿表示後に必要な場合だけ追加取得する。

### 4.5 過去の未保存授業

【現行コードから確認できた事実】

- 過去未保存サマリーは「担当授業」パネルの先頭、今日／過去タブより上にある。
- `getTeacherUnsavedSummaryFast()`が`ready`の場合、未保存件数、対象期間、最終確認時刻を表示する。
- 件数が1件以上の場合だけ`詳細を見る`を表示する。
- `missing`、`stale`、`building`、`error`、その他のunavailable状態を表示上区別する。
- Fast APIに失敗しても、授業一覧と出席入力は利用可能である旨を表示する。
- 詳細を初めて開いたときに`getTeacherUnsavedDetailsFast({ limit: 50, offset: 0 })`を呼ぶ。
- 詳細行は日付・時限、科目名、対象クラスまたは班、授業回数、`この授業を開く`を表示する。
- `この授業を開く`は過去モードへ切り替え、対象日を検索して一致する授業を選択する。
- `hasMore`が`true`の場合も、現行UIは50件を超える詳細を追加取得せず、今後のページング対応で表示する旨だけを出す。
- 過去未保存授業を保存すると、詳細項目とサマリー件数をクライアント側で減算する。

### 4.6 Loading、Empty、Error

【現行コードから確認できた事実】

| 対象 | Loading | Empty | Error |
|---|---|---|---|
| 授業一覧 | `授業情報を読み込み中...` | `今日の授業はありません。`または`該当日の担当授業はありません。` | 一覧、選択情報、入力領域へ読み込み失敗を表示し、共通messageも表示 |
| 保存状態 | カードに`確認中...` | 保存記録がなければ`未保存` | `確認失敗`、補助文、クイック保存disabled |
| 名簿 | `学生一覧を読み込み中...` | `学生が見つかりませんでした。` | 名簿または保存済み出欠の読み込み失敗を表示 |
| 工学実験の班 | `担当可能な班を読み込み中...` | 班未選択なら選択案内 | 共通messageへ班一覧取得失敗を表示 |
| 過去未保存サマリー | 自動確認中の文言 | `未保存の授業はありません` | Fast APIの状態別メッセージまたは呼び出し失敗 |
| 過去未保存詳細 | 一覧読み込み中 | `未保存授業はありません。` | 詳細取得失敗またはcache状態メッセージ |
| 保存 | 保存中のmessageと操作disabled | 該当なし | 共通messageと入力領域へ保存失敗を表示 |

授業一覧、名簿、保存結果の多くは同じ`.empty-box`を使っており、loading、empty、success、errorの視覚上の差は限定的である。失敗表示に再試行ボタンはない。

【現行コードから確認できた事実】

- 授業選択後に出席入力パネルへ自動スクロールまたはフォーカス移動する処理はない。

## 5. 現行UIの課題

### 5.1 現行コードから確認できた事実

1. 過去未保存サマリーが今日／過去タブより先にあり、詳細展開時は今日の授業一覧を下へ押し下げる。
2. 通常カードには意味の異なる2操作が同程度の大きさで並び、どちらが標準の出席入力か判断が必要になる。
3. カード本体はpointerとhoverを持つがクリックできず、見た目と操作可能範囲が一致しない。
4. 日付、授業回数、担当教員、最終保存時刻が同じメタ領域へ連続表示され、科目名とクラスの視覚的な優先度との差が小さい。
5. 概要は0件の状態も含めて5chipすべてを表示するため、授業数が少ない日でも情報量が一定である。
6. 入力途中は右パネルの`saveState`だけに表示され、授業カード側には反映されない。
7. 900px以下ではカード一覧と入力領域が縦に離れるが、選択後の移動支援がない。
8. 過去モードは今日の一覧を置き換えるため、過去対応中に今日の進捗を同時確認できない。
9. loading、empty、errorの多くが同じ枠の文言差であり、再試行導線がない。
10. mode tabに`aria-selected`等はなく、共通messageと保存状態に`aria-live`は設定されていない。
11. `:focus-visible`の統一スタイルがない。
12. 教室情報は現行APIにない。

### 5.2 UX上の改善候補

【Step1-Cでの提案】

- 今日の授業をページの主見出し直下へ置き、過去未保存はコンパクトな通知として従属させる。
- 授業カードの主操作を明示的なbuttonへ一本化し、クイック保存は副操作として見せる。
- 時限と科目名を最初に読み取れるよう、カードの情報をprimary、secondary、status、actionへ分ける。
- 入力途中を`isDirty`から表示し、選択中授業と未保存変更の関係を明確にする。
- モバイルでは授業選択後に入力見出しへフォーカスまたはスクロールし、戻り導線も用意する。
- loading、empty、errorを役割ごとのcomponentとして整理し、既存APIを再実行する再試行操作を必要箇所へ置く。
- 過去検索は今日と同格の常設タブではなく、「過去授業を修正する」補助導線として扱う。ただし内部の`currentMode`は維持する。

## 6. UI設計原則

【Step1-Cでの提案】

1. **今日を最優先にする。** 初期表示で今日の件数、状態、授業カード、主操作が最初に読める順序を守る。
2. **1カード1判断にする。** 「どの授業か」「現在どういう状態か」「次に何を押すか」をカード内で分離する。
3. **主操作を明示する。** カード全体を曖昧なクリック領域にせず、動詞を持つbuttonを操作起点にする。
4. **状態は文字を主、色を補助にする。** badgeのラベル、補助文、disabled理由を維持し、色だけで伝えない。
5. **段階的に情報を開示する。** 過去未保存詳細、欠席リスク、過去検索は必要なときだけ展開する。
6. **既存契約を境界にする。** 現行APIと保存payloadで取得・判定できる内容だけを表示する。
7. **画面幅ではなく作業の連続性を守る。** 1列化したときも、選択した授業、入力領域、戻り先を見失わせない。

### 6.1 視覚デザイン方針

【Step1-Cでの提案】

| 要素 | 方針 |
|---|---|
| card | 白を基本に、時限・科目・クラス・状態・操作を一定の順序で配置する。状態色で全面を塗らない |
| spacing | 4pxまたは8pxを基準単位とし、card内12〜16px、card間12px、section間24〜32pxを目安にする |
| typography | ページ見出し22〜24px、section見出し18〜20px、科目名16px以上、本文14px以上、補助情報12〜13px以上を基準にする |
| section heading | 見出し、対象日または件数、補助操作を1つのheaderとしてまとめ、sectionの開始位置を明確にする |
| button hierarchy | Primaryは塗り、Secondaryはoutlineまたは弱い背景、補助操作はtextまたは中立色とし、同じ強さのbuttonを並べすぎない |
| status badge | 文字ラベルを必須にし、淡い背景、border、必要に応じたiconを併用する。色だけで意味を持たせない |
| border | panelとcardは中立色の1px borderを基本にし、未入力やerrorは左線またはbadgeで補助する |
| shadow | 常時はなし、または現行より弱いshadowに抑える。選択中の強調にも過大なshadowを使わない |
| background | ページは薄い中立色、sectionとcardは白を基本にして階層を作る。状態ごとの強い全面色を避ける |
| hover | mouse利用時だけ操作可能なbuttonやlinkを明確にする。非clickable card全体にはhoverを付けない |
| active | 選択中cardはborder、背景、`選択中`の文字を併用し、focusとは別の状態として表す |
| disabled | opacityだけに頼らず、cursor、色、`disabled`属性、近接する理由文を組み合わせる |

## 7. 新しいページ構成案

【Step1-Cでの提案】

Step1-Cでも`today`と`past`の単一アクティブモードを維持する。今日と過去の授業一覧を同時に保持する新しい状態管理は導入しない。


## 8. 今日の授業セクション

【Step1-Cでの提案】

### 8.1 情報の優先順位

1. セクション名「今日の授業」と対象日
2. 表示カード件数と、対応が必要な件数
3. 各授業の時限、科目、クラス
4. 保存状態
5. 主操作
6. 授業回数、担当、最終保存等の補助情報

概要chipは全状態を常に並べず、0件の項目を省略するか、`未入力 2 / 保存済み 2`のように短くする。`確認中`または`確認失敗`がある場合は、安全判断に必要なため0件でないものを必ず表示する。工学実験の`一部保存済み`も存在時だけ表示する。

### 8.2 主操作の選択

カード全体クリックは採用しない。カード内に異なる結果を持つ`出席を入力・確認`と`欠席者なしで保存`が共存し、カード全体のclickがどちらを意味するか曖昧になるためである。

推奨する操作階層は次のとおりである。

- Primary: `出席を入力・確認`
- Secondary: `欠席者なしで保存`
- 工学実験のPrimary: `班を選択して入力`

表示文言を変更する場合も、内部の`data-action="input-absence"`、`data-action="no-absence"`と既存click handlerは維持する。クイック保存の確認ダイアログと、確認中・確認失敗時のdisabledも維持する。

### 8.3 過去授業検索への導線

`過去授業を検索`は今日の授業と同じ強さの主タブではなく、セクション右上または下部の`過去授業を修正する`として表示する。選択後は既存の`past`モードへ切り替え、見出しを「過去授業の修正」、戻り操作を「今日の授業へ戻る」と明示する。

## 9. 授業カード仕様案

【Step1-Cでの提案】

### 9.1 共通構造

```text
article.lesson-card
├─ header
│  ├─ 時限
│  └─ 状態badge
├─ 科目名
├─ クラスまたは「班選択して記録」
├─ 補助情報（授業回数、担当、最終保存）
├─ 状態補助文（必要な場合だけ）
└─ actions
   ├─ Primary
   └─ Secondary（通常授業だけ）
```

カード本体から`cursor: pointer`を外し、buttonだけを操作可能に見せる。選択済みカードは`active`の枠に加えて「選択中」の文字またはscreen reader向けラベルを付ける。

### 9.2 Desktop

- 時限badgeと状態badgeを同じ行に置く。
- 科目名は16px以上、太字、最大2行を許容する。
- クラスを科目名の直下に置く。
- 日付は今日セクションでは重複するため視覚的に省略可能だが、DOMまたは詳細情報では保持する。
- 授業回数、担当、最終保存は小さな補助情報として1〜2行にまとめる。
- Primaryを先、Secondaryを後に置き、色、塗り、位置で主従を明確にする。

### 9.3 Mobile

- 時限と状態を同じ行に保つ。
- 科目名、クラスを折り返し可能にし、省略によって識別不能にしない。
- Primary、Secondaryを縦並びの全幅buttonにする。
- 最小タップ領域は44pxを確保する。
- 担当や最終保存等は折りたたまず、短い補助行としてカード下部に置く。長い担当者一覧は自然改行を許可する。

### 9.4 状態表示

| 表示状態 | 判定根拠 | 表示案 |
|---|---|---|
| 未入力 | 保存状態取得済みで保存記録なし | `未入力`badge。現行内部状態`unsaved`を利用 |
| 入力途中 | 選択中かつ`isDirty === true` | `入力途中（未保存）`。クライアントだけの一時表示 |
| 保存済み | `isSaved`または保存済みsession key | `保存済み`badge＋必要なら最終保存 |
| 一部保存済み | 工学実験の関連クラスの一部が保存済み | 現行ラベルを維持 |
| 確認中 | 保存状態後読み中 | `確認中`badge＋クイック保存disabled |
| 確認失敗 | 保存状態API失敗または項目欠落 | `確認失敗`badge＋文字の案内 |
| 過去未保存 | Fast詳細に存在 | 今日のカード状態とは混在させず、過去未保存詳細内で表示 |
| 授業なし | 一覧が空 | セクション単位のempty state |

`未入力`への文言変更は表示上の提案であり、新しいサーバー状態は追加しない。既存の`unsaved`を教員向けに言い換えるだけとする。

## 10. 過去未保存授業セクション

【Step1-Cでの提案】

### 10.1 二段階構造

第1段階はコンパクトな通知である。

```text
過去の未保存授業 3件
対象期間: 2026-04-07〜2026-08-16 / 最終確認: 2026-08-17 06:50
[詳細を見る]
```

第2段階は教員が`詳細を見る`を押した場合だけ表示する詳細一覧である。各行は日付・時限、科目、クラスまたは班、授業回数、`この授業を開く`を保持する。

### 10.2 Fast API契約

- `getTeacherUnsavedSummaryFast()`と`getTeacherUnsavedDetailsFast()`をそのまま使う。
- `ready`以外を成功扱いにしない。
- `checkedAt`と対象期間を表示し、キャッシュ情報であることを隠さない。
- `missing`、`stale`、`building`は注意、`error`、`unavailable`、呼び出し失敗はエラーとして文言を分ける。
- Fast APIが利用できなくても、今日の授業と出席入力を止めない。
- Step1-Cでは現行どおり最初の50件を表示する。追加読み込みは既存`offset`で実現可能だが、画面再構成と混ぜず別の改善候補とする。

### 10.3 表示位置

サマリー通知は今日のセクション見出しと件数概要の後、カード一覧の直前に置いてよい。ただし初期状態では1行程度に抑え、詳細を自動展開しない。教員が展開を選んだ場合にだけ今日のカードが下へ移動することは許容する。

0件の場合は成功を伝える短い中立表示にし、今日の授業より強い青背景にはしない。エラーの場合も「今日の出席入力は利用できます」を併記する。

## 11. Loading / Empty / Error

【Step1-Cでの提案】

| 状態 | UI方針 | 操作 |
|---|---|---|
| 今日の授業loading | セクション見出しとカード骨格を維持し、短いloading表示 | 二重実行を防ぐ。過去未保存は独立して後読み |
| 今日の授業empty | `今日の担当授業はありません`を明示 | 過去授業修正、過去未保存確認は利用可能 |
| 今日の授業error | 赤だけに頼らないerror見出しと説明 | `再読み込み`で既存`loadTodayClasses()`を再実行 |
| 保存状態loading | カードの`確認中`を維持 | Primary入力は利用可能、クイック保存はdisabled |
| 保存状態error | `確認失敗`と理由をカード内表示 | Primary入力は利用可能、クイック保存はdisabled |
| 名簿loading | 選択授業情報を残し、その下だけloading | 授業切替時のrequest tokenを維持 |
| 名簿empty | `対象学生が見つかりません` | 保存buttonをdisabled |
| 名簿error | 対象授業を残して失敗を表示 | `再試行`で同じ授業・班を読み直す |
| 保存中 | 対象授業と入力内容を維持し、buttonをdisabled | 多重保存を防ぐ |
| 保存error | 入力状態を保持し、共通messageと入力領域近くに表示 | 再保存可能。`isDirty`を維持 |
| 未保存サマリーloading | 小さなprogress文言 | 今日の操作を妨げない |
| 未保存サマリーempty | `過去の未保存授業はありません` | 詳細buttonを隠す |
| 未保存サマリーerror | cache状態と利用可能な範囲を説明 | 既存Fast APIの再試行buttonを検討 |

loadingには`aria-busy`、非同期結果の短いメッセージには適切な`aria-live`を付ける。errorからの再試行は既存クライアント関数を再実行するだけとし、新しいserver APIを追加しない。

## 13. Accessibility

【Step1-Cでの提案】

- ページ、今日の授業、過去未保存、出席入力、補助操作を`header`、`main`、`section`等で意味付けする。
- 授業カードは情報のまとまりとして`article`またはlist itemにし、操作は必ず`button`にする。
- mode切替を残す場合は`role="tablist"`、`aria-selected`、対応panelを設定する。補助導線へ変更する場合は通常のbuttonとして実装する。
- 状態badgeには必ず文字を表示し、色、border style、iconは補助にする。
- `messageArea`、保存結果、loading完了には内容に応じた`aria-live="polite"`または`role="alert"`を設定する。
- `:focus-visible`で2px以上の明確なoutlineを表示する。
- Primary、Secondary、status buttonは44px以上の操作領域を確保する。
- disabled時は見た目だけでなく`disabled`属性を維持し、理由を近接する文字で示す。
- 科目名やクラスを色や省略だけで区別しない。
- 文字サイズは本文14px以上、補助情報12〜13px以上を基準とし、200%拡大でも主要操作が重ならないことを確認する。
- コントラストは通常文字4.5:1、large textやUI境界3:1を目安に確認する。
- 自動スクロールを行う場合は同時に見出しへfocusを移し、移動先をscreen readerにも伝える。

## 17. リスク

1. **操作handlerの欠落**: カードDOMを変更した際に`data-action`または`data-sidebar-key`を失うと、入力・クイック保存が動かなくなる。
2. **非同期状態の逆転**: 授業一覧、保存状態、名簿、未保存Fast APIが別々に完了する。古い応答を新しい選択へ描画しないrequest tokenを維持する必要がある。
3. **未保存変更の喪失**: mode、授業、班の切替導線を変えても`isDirty`確認を迂回してはならない。
4. **クイック保存の安全性低下**: Primary／Secondaryの見た目変更で、確認中または確認失敗時にクイック保存が有効化されないようにする。
5. **工学実験の回帰**: 通常カード前提のDOMへ寄せると、集約カード、班選択、一部保存状態が壊れる可能性がある。
6. **過去未保存導線の回帰**: 詳細から過去モードへ移り、対象日検索後に該当授業を自動選択する処理を維持する必要がある。
7. **サマリー不整合**: 保存後のローカル減算とカード状態更新が別々に走るため、表示箇所を増やすと同期漏れが起こり得る。
8. **モバイルの移動量**: 1列レイアウトで自動移動だけを追加すると、元の授業へ戻れなくなる。戻りbuttonとfocus管理を対で設計する。
9. **tableの狭幅化**: 出席状態buttonと欠席リスク列が多く、カード改善だけではスマートフォンの横スクロール問題が残る。
10. **管理者表示の回帰**: なりすましUIを通常教員画面だけの想定で隠したり、header再構成で操作不能にしたりしない。
11. **視覚変更による誤認**: `未入力`、`入力途中`、`保存済み`の意味が近いため、文言と判定根拠を実装・テストで一致させる。
12. **教室情報の誤記載**: 現行APIにない項目を空欄表示や仮表示しない。

## 19. 推奨実装順序

### Step1-C-2 ページ骨格と情報階層
